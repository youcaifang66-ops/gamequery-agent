# 千万级合成业务数据与容量实证

Status: Approved (standing user authorization)
Version: 1.0
Mode: Full
Last updated: 2026-09-24

## Overview

为 GameQuery 建立一套可重复生成、可安全灌入、带业务标准答案且不会夸大结论的千万级游戏运营数据实验。交付物必须让另一台机器能够重现实验，并清楚区分“生成成功”“数据库实测”“Agent 业务效果”三种证据。

## User Stories

### Primary

作为项目维护者，我希望生成并验证至少 1,000 万条游戏运营事实数据，以便在有证据的规模上测试查询正确性和容量性能。

### Secondary

作为面试者，我希望每个性能或业务效果数字都能追溯到数据版本、标准答案和实验环境，以便明确回答项目已经证明和尚未证明的能力。

## Assumptions Resolved

- `[RESOLVED]` 目标规模：本轮必须真实生成并验证 10,000,000 条事实记录；不以参数存在代替生成证据。
- `[RESOLVED]` 数据来源：公开资料用于事件模型和分布设计参考；不下载或混入来源/许可不清的玩家级原始数据。
- `[RESOLVED]` 业务真实性：使用带趋势、长尾、活动峰值和付费偏态的合成数据，并明确标记 synthetic。
- `[RESOLVED]` 数据保存：大型数据文件不进入 Git；仓库只保存生成、导入、校验工具及小型证据报告。
- `[RESOLVED]` 容量声明：只有完成数据库导入和固定工作负载实测的规模才可声明；环境不可用时必须报告未运行。

## Boundaries

**Always do:**

- 固定随机种子、数据版本、总行数、文件摘要和生成环境。
- 生成标准答案时使用与事实行同源但独立的聚合账本，并用小规模全扫描交叉验证账本。
- 导入只允许进入显式指定的实验数据库，不修改默认演示数据库。
- 每份报告标明 synthetic、measured/not_run 和最大可声明行数。

**Never do:**

- 提交千万行 CSV、密码、真实玩家标识或第三方原始数据文件。
- 把数据成功生成表述为数据库或 Agent 已支持该规模。
- 把固定 SQL 标准答案表述为真实模型准确率。
- 在未记录硬件、版本、索引、预热和并发的情况下发布性能数字。

## Acceptance Criteria

### AC-01: 千万级精确生成 [MUST]

Given 选择 `10m` 数据规模和固定种子
When 生成任务正常完成
Then 三张事实数据文件合计恰好包含 10,000,000 条记录，manifest 记录各文件行数、字节数和摘要。

### AC-02: 可重复生成 [MUST]

Given 相同数据版本、规模和随机种子
When 在相同实现上重复生成小型验证集
Then 每个输出文件和标准答案文件的 SHA-256 完全一致；不同种子至少一个事实文件摘要不同。

### AC-03: 有界资源和实测生成报告 [MUST]

Given 当前执行机器生成 10,000,000 条事实记录
When 生成完成
Then 报告记录墙钟时间、峰值进程内存、输出字节数、操作系统、CPU、内存、运行时版本与提交 SHA；峰值进程内存不超过 1 GiB。

### AC-04: 业务分布特征 [MUST]

Given 任一非 smoke 数据集
When 校验业务分布
Then 报告证明游戏事件具有长尾集中度、周末活跃提升、至少一个活动日期峰值、右偏付费金额和非零未通关事件，并记录每项实际值及约定阈值。

### AC-05: 标准业务问题与答案 [MUST]

Given 已生成的数据集
When 读取标准答案清单
Then 至少包含 DAU、收入、付费人数、ARPU、关卡通过率和渠道拆分六类问题，每条记录问题、标准 SQL、参数、列和精确预期结果。

### AC-06: 标准答案独立交叉验证 [MUST]

Given smoke 数据集
When 使用生成账本和对 CSV 的独立扫描分别计算六类答案
Then 两种计算结果完全一致；任一差异使校验失败。

### AC-07: 来源和隐私边界 [MUST]

Given 任意生成 manifest
When 审计 provenance
Then 它声明数据为 synthetic、无真实玩家数据，列出分布设计参考的 URL、许可证或文档类型，并记录生成器版本。

### AC-08: 安全批量导入 [MUST]

Given 已校验的数据目录和显式实验数据库名
When 执行导入
Then 工具拒绝路径外文件、拒绝默认业务数据库、拒绝只读账号，并通过批量装载将维度和事实数据写入独立实验数据库。

### AC-09: 导入后完整性 [MUST]

Given 批量导入成功
When 执行导入验收
Then 数据库表行数与 manifest 完全一致，六类标准答案与数据库查询结果完全一致，报告记录导入耗时和吞吐量。

### AC-10: 数据库固定工作负载 [MUST]

Given 已导入的数据集
When 以并发 1 在预热后重复运行六类标准查询至少 30 次
Then 生成包含每类查询样本数、成功率、p50/p95/p99、最大值和查询计划摘要的数据库报告。

### AC-11: 并发容量阶梯 [SHOULD]

Given 已导入的 10,000,000 行数据集
When 分别以并发 1、5、10、20 运行固定工作负载
Then 每一档独立记录吞吐、成功率、p50/p95/p99、超时率和资源环境，不跨档或跨机器外推。

### AC-12: 报告真实性 [MUST]

Given 生成、导入或查询阶段未运行或失败
When 输出实验摘要
Then 对应状态为 `not_run` 或 `failed`，指标为空且包含稳定原因；任何报告最大声明行数不得超过已实测行数。

### AC-13: CI 小规模合同 [MUST]

Given CI 的受限时间与磁盘
When 运行质量门禁
Then 使用 smoke 数据验证生成、分布、标准答案、导入合同和报告结构，不在 CI 生成千万行或调用真实模型。

### AC-14: 现有 Agent 兼容 [UNCHANGED] [MUST]

Given 完成数据和容量工具升级
When 运行既有回归
Then `/health`、`/api/query`、SSE、SQL 安全、检索、追踪和前端构建继续通过。

### AC-15: 大型产物隔离 [MUST]

Given 在仓库工作区内指定实验输出目录
When 生成大型 CSV 或原始负载结果
Then Git 忽略这些产物，且提交历史中不存在单个生成数据文件。

### AC-E1: 非法规模或输出路径 [MUST]

Given 行数非正、目标路径为仓库根目录或路径不可写
When 请求生成
Then 在写出事实数据前失败，并返回明确错误。

### AC-E2: 损坏或不匹配的数据集 [MUST]

Given manifest 摘要、行数或标准答案与文件不一致
When 请求校验或导入
Then 操作在连接数据库或改变实验库之前失败，并指出不匹配文件。

### AC-W1: 真实企业数据 [WONT]

本轮不导入真实企业玩家、支付或行为数据；原因是仓库没有授权数据源、数据处理协议和隐私审查。

### AC-W2: 真实业务提效结论 [WONT]

本轮不声明运营人员完成时间或人工替代率；该结论需要真实用户对照实验。

### AC-W3: 真实 LLM 准确率 [WONT]

本轮不在 CI 或无凭据环境调用真实模型；只交付可供后续真实模型评测使用的标准问题与答案。

## Out of Scope

- 修改线上 `/api/query` 合同或开放公网访问。
- 引入数据湖、流式消息队列或新的生产数据库。
- 自动下载第三方数据集。
- 用 GitHub 托管 runner 的瞬时硬件结果代表生产 SLA。
- 直接声称支持超过实际导入和测量规模的数据量。

## Non-Functional Requirements

- 可复现性：所有生成和报告包含 seed、版本、提交 SHA 与 SHA-256。
- 内存：千万行生成峰值进程 RSS ≤ 1 GiB。
- 安全：大型数据仅写入显式目录；数据库密码仅从环境变量读取；只读账号不得导入。
- 可移植性：生成与离线校验在 Python 3.12 的 Windows 和 Linux 上工作。
- 证据：正式容量数字必须来自保存的报告，而不是终端中一次性输出。
