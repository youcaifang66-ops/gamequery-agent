# 数据库工作负载与结构优化

Status: Approved
Version: 1.0
Mode: Full
Baseline: `specs/database-workload-optimization/research.md` F-1..F-7
Last updated: 2026-09-25

## Overview

在保持现有问数接口、安全边界和千万级事实数据不变的前提下，补齐玩家下钻核查场景，修复指标真值冲突，并以可复现基准证明优化前后的查询性能。

## User Stories

### Primary

作为游戏运营或客服，我希望按玩家标识快速核查玩家画像、活跃、支付和关卡轨迹，以便定位单个玩家问题，而不必等待全量数据扫描。

### Secondary

作为数据负责人，我希望每个性能与指标结论都有标准答案、执行计划和优化前后报告，以便区分真实改进与缓存或口径变化造成的假提升。

## Boundaries

**Always do:**

- 玩家跨域核查必须分别读取各业务域并汇总，不制造多对多结果膨胀。
- 优化前后必须使用相同数据、相同参数、相同预热和样本数。
- 查询结果正确性优先于延迟；任何结果不一致均使性能验收失败。
- 新增结构必须有对应查询模式、回滚方式和存储成本证据。

**Ask first:**

- 引入新的数据库产品、消息系统或云服务。
- 增加不属于活跃、支付、关卡、玩家画像的业务域。

**Never do:**

- 为展示规模而增加无查询用途的表或索引。
- 把三个一对多业务域直接连接成一个乘积结果集。
- 使用真实玩家、支付或身份数据。
- 扩大在线查询账号的权限。

## Acceptance Criteria

### AC-01: 玩家全域核查正确性 [MUST]

Given 千万级合成数据和一个存在的玩家标识
When 分别查询玩家画像、活跃、支付和关卡记录
Then 四类结果与优化前逐行一致，且总行数和内容摘要完全一致。

### AC-02: 玩家查询延迟 [MUST]

Given 千万级合成数据、3 次预热和每类至少 30 个计时样本
When 以单并发查询单个玩家的三类事实记录
Then 每类查询 P95 不超过 50 ms，且零超时、零错误、零结果不匹配。

### AC-03: 玩家查询并发 [MUST]

Given 与 AC-02 相同的数据和查询
When 以并发 20 分别执行每类玩家查询至少 30 次
Then 每类查询 P95 不超过 200 ms，且零超时、零错误、零结果不匹配。

### AC-04: 执行计划可核验 [MUST]

Given 任一存在或不存在的玩家标识
When 检查三类玩家事实查询的实际执行计划
Then 每个查询都使用与玩家条件匹配的访问路径，不出现全量表扫描，并记录估算行、实际行和实际耗时。

### AC-05: 运营查询不回退 [MUST]

Given 既有六类固定查询和相同实验环境
When 重新执行单并发与并发 20 基准
Then 所有结果保持一致；除月收入外每类 P95 不高于既有报告的 120%，月收入单并发 P95 不超过 150 ms、并发 20 P95 不超过 500 ms。

### AC-06: 关卡通过率真值统一 [MUST]

Given 同一批关卡事件数据
When 在线指标、生成账本、独立扫描和数据库真值分别计算指定关卡通过率
Then 四者均采用“通过数之和除以尝试次数之和”，结果完全一致。

### AC-07: 可重复结构迁移 [MUST]

Given 已导入的千万级实验库
When 应用结构优化一次或重复执行检查
Then 首次只创建缺失结构，重复执行不产生重复对象；迁移记录耗时、前后结构和回滚语句，并刷新优化器统计。

### AC-08: 成本证据 [MUST]

Given 优化前后的同一实验库
When 生成验证报告
Then 报告同时记录每张表的数据字节、索引字节、索引创建耗时及查询延迟变化，不只报告加速比例。

### AC-09: 现有 Agent 兼容 [UNCHANGED] [MUST]

Given 数据结构优化完成
When 运行现有质量门禁和网页示例
Then `/health`、`/api/query`、SSE、SQL 安全、检索、只读权限和前端构建继续通过。

### AC-E1: 不存在的玩家 [MUST]

Given 一个格式合法但不存在的玩家标识
When 执行玩家核查
Then 四类结果为空，查询仍使用受控访问路径且不扫描全部事实数据。

### AC-E2: 迁移权限或目标错误 [MUST]

Given 只读账号、默认业务库或不符合实验库命名规则的目标
When 请求结构迁移
Then 在任何结构变化前失败，并返回稳定、可识别的错误。

### AC-W1: 日期分区 [WONT]

本轮不增加日期分区；当前规模没有证明分区收益，且现有唯一键与分区约束不兼容。

### AC-W2: 新分析数据库 [WONT]

本轮不引入新的列式或分布式数据库；先完成当前技术栈内的工作负载优化与证据闭环。

### AC-W3: 新业务事件域 [WONT]

本轮不增加广告、道具、会话、退款或社交事件；这些需要独立业务规格、数据合同和指标定义。

## Out of Scope

- 真实生产零停机迁移、复制拓扑和云数据库运维。
- 真实用户数据、隐私处理和租户隔离。
- 超过 1000 万事实行的容量声明。
- 修改公开 API 或允许无界玩家历史返回。

## Open Questions

- [RESOLVED] 玩家跨域数据是否直接连接？→ 否，按业务域独立查询并由调用方汇总。
- [RESOLVED] 哪个关卡通过率口径权威？→ 版本化指标定义中的“通过数之和 / 尝试次数之和”。
- [RESOLVED] 是否立即分区或换 OLAP 数据库？→ 否，等待更大规模和归档需求证据。

## Non-Functional Requirements

- 性能：以 AC-02、AC-03、AC-05 的 P95 阈值为准；每类至少 30 个成功样本。
- 正确性：所有基准先比对标准答案，再接纳延迟样本。
- 安全：线上账号保持只读；结构变更只允许显式实验库和管理账号。
- 可复现性：报告记录提交 SHA、时间、系统、数据库版本、数据摘要、预热、并发和完整样本。
- 可回滚性：所有新增结构均提供独立回滚语句；不删除现有结构。
