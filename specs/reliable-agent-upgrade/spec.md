# GameQuery 可靠性与可验证能力补全

Status: Approved by standing user authorization
Version: 1.0
Mode: Full
Baseline: `specs/reliable-agent-upgrade/research.md`
Last updated: 2026-09-23

## Overview

把现有演示型 Text-to-SQL 链路补全为安全、可追踪、可评测、可回归的工程版本。升级后仍使用现有问数入口和流式交互，但每条 SQL、每次检索和每项指标都必须留下可验证证据。

## User Stories

### Primary

作为游戏数据分析人员，我希望用自然语言查询运营指标，并且只获得经过安全校验和数据库预检的结果，从而不需要手写 SQL，也不会误修改数据。

### Secondary

作为研发和面试评审者，我希望能够回放一次查询、解释候选信息为何被召回，并复现质量与性能指标，从而判断项目能力是否真实。

作为项目维护者，我希望外部服务失败、模型输出错误或数据库拒绝 SQL 时得到稳定错误码和完整测试证据，从而可以定位问题而不泄露内部异常。

## Assumptions

- 本轮服务面向本地演示或已鉴权可信网关后的单租户部署，不在应用内新增用户体系。
- 在线查询只处理只读分析问题；写数据、建表、管理账号和自由执行用户 SQL 都不属于产品能力。
- CI 必须完全确定性，不依赖收费模型或公网服务；真实模型和完整容器环境只作为显式可选评测。
- 最大返回行数固定为 500；单次工作流最多自动纠错 2 次；整次请求默认截止时间为 60 秒。
- 质量门槛先证明安全与可复现性，不宣称未经目标环境压测的“千万级”能力。

## Boundaries

**Always do:**

- 所有生成 SQL 与纠错 SQL 在执行前走同一安全链路。
- 所有在线事件携带可关联的请求标识，并且每次请求只产生一个终态。
- 所有质量指标标明数据集、计算方式、运行模式与时间。
- 每个 `[MUST]` 标准至少由一个自动化测试覆盖。

**Ask first (do not proceed unilaterally):**

- 改变现有 `/api/query` 请求体中 `query` 的含义或删除现有 SSE payload 字段。
- 新增业务数据库表、改变线上事实表结构或引入需要运维的新外部服务。
- 把本地单租户边界扩大为公网多租户鉴权系统。

**Never do:**

- 执行未通过安全校验和数据库预检的 SQL。
- 记录数据库密码、模型 Token、完整查询结果或原始内部堆栈。
- 把人工预置答案、人工修复 SQL 或 mock 结果标记为真实 Agent 成功率。
- 在字段、指标、业务值三种不同实体之间计算一个没有语义解释的总排名。

## Acceptance Criteria

### AC-01: 单条只读 SQL 边界 [MUST]

Given 候选 SQL 包含写操作、DDL、事务命令、多条语句或未允许的系统表
When 工作流准备验证该候选 SQL
Then 在任何数据库调用前拒绝它，并返回稳定的安全错误码。

### AC-02: 表与字段白名单 [MUST]

Given 候选 SQL 引用了元数据白名单之外的表或字段
When 安全校验运行
Then SQL 不被执行，错误中只包含稳定错误码和经过清理的对象名。

### AC-03: 强制结果上限 [MUST]

Given 候选查询没有 `LIMIT`、`LIMIT` 大于 500 或 `LIMIT` 不可静态确定
When 安全校验完成
Then 可执行 SQL 的最大返回行数不超过 500；小于等于 500 的显式限制保持不变。

### AC-04: 纵深校验与同一 SQL 执行 [MUST]

Given 一个通过静态安全校验的候选 SQL
When 工作流进入数据库阶段
Then 先对规范化后的同一 SQL 做数据库预检，只有预检成功后才允许执行该 SQL。

### AC-05: 有界纠错闭环 [MUST]

Given SQL 出现可修复的解析、表字段或数据库预检错误
When 工作流触发自动纠错
Then 最多纠错 2 次，每个新候选都重新执行完整安全链路；成功后执行，仍失败则产生一个终态错误。

### AC-06: 不可纠错安全违规 [MUST]

Given SQL 含写操作、多语句、事务命令或系统对象访问
When 安全校验拒绝该 SQL
Then 工作流不把原 SQL 和安全错误交给模型继续纠错，并以安全拒绝终止。

### AC-07: 数据库最小权限 [MUST]

Given 在线查询账号连接到业务数仓
When 尝试 `SELECT` 与任一 `INSERT`、`UPDATE`、`DELETE`、`CREATE` 或 `DROP`
Then `SELECT` 可用且所有写入和结构变更都被数据库权限拒绝。

### AC-08: 查询截止时间 [MUST]

Given 数据库预检或执行超过配置的时间预算
When 截止时间到达
Then 操作被取消或中断，连接可继续复用，并返回 `QUERY_TIMEOUT`，不返回驱动异常文本。

### AC-09: 稳定错误契约 [MUST]

Given 模型、Embedding、检索库、数据库或工作流节点抛出异常
When 流式响应已经开始
Then 客户端收到一个含请求标识、稳定错误码和安全消息的终态错误事件，且看不到密码、连接串或堆栈。

### AC-10: SSE 向后兼容与终态 [MUST]

Given 现有客户端按 payload 中的 `type` 消费 `/api/query`
When 查询成功、失败或超时
Then 原有 `type` 字段继续可用，每个事件增加同一请求标识，并且流恰好以一个 `done` 或 `error` 终态结束。

### AC-11: 可回放审计追踪 [MUST]

Given 任意一次在线查询
When 查询开始、产生节点事件并结束
Then 系统持久化按序事件、状态、耗时和错误码，并可按请求标识回放；追踪不保存完整结果集或凭据。

### AC-12: 追踪并发一致性 [MUST]

Given 至少 20 个查询并发写入各自追踪
When 所有查询结束后分别回放
Then 每条追踪序号从 1 连续递增、事件不串线、终态唯一且数据库无锁错误。

### AC-13: 工作流汇合回归 [MUST]

Given 三条召回分支和两条过滤分支以不同完成顺序返回
When 工作流运行
Then 每个汇合后的节点只执行一次，并且能够读取全部前驱结果。

### AC-14: 同类多通道检索证据 [MUST]

Given 同一字段或同一指标被精确词、别名、向量或扩展词中的一个或多个通道命中
When 候选结果输出给后续节点
Then 候选只出现一次，并携带每个命中通道、通道内排名和可复算的融合贡献。

### AC-15: 检索类型隔离 [MUST]

Given 字段、指标和业务值三类召回同时完成
When 系统排序与合并候选
Then 排名融合只发生在同一实体类型内部，跨类型信息只按明确关系补齐上下文。

### AC-16: 检索确定性 [MUST]

Given 输入候选、通道顺序和配置完全相同
When 重复运行融合 100 次
Then 候选顺序、分数和证据完全相同。

### AC-17: 信息不足时澄清 [SHOULD]

Given 问题缺少指标必需的日期、无法识别游戏实体或同时命中多个冲突口径
When 工作流准备生成 SQL
Then 返回结构化澄清事件说明缺少或冲突的槽位，而不是猜测 SQL 并执行。

### AC-18: 确定性端到端测试 [MUST]

Given 受控的模型替身、检索结果和数据库替身
When 从自然语言请求运行完整工作流
Then 测试覆盖成功、一次纠错成功、纠错耗尽、安全拒绝、外部依赖失败与超时六类路径，并验证节点顺序和终态。

### AC-19: 真实容器集成测试 [SHOULD]

Given 本地容器环境已启动且不需要真实 LLM
When 运行集成测试标记
Then 验证只读数据库权限、SQL 预检/执行、检索服务连通和追踪持久化；未启动环境时明确跳过而不是误报通过。

### AC-20: 检索黄金集与消融 [MUST]

Given 至少 30 条覆盖字段、指标、别名、真实业务值和无匹配场景的黄金问题
When 运行离线检索评测
Then 输出各通道及融合后的 Hit@5、MRR、无匹配误召率和样本级证据，并能比较启用/关闭融合的差异。

### AC-21: SQL 指标真实性 [MUST]

Given SQL 工作集含首轮正确、可修复和不安全样本
When 运行离线评测
Then 分别报告静态 Guard 准确率、预置修复可执行率和真实 Agent 纠错率；没有运行真实 Agent 时后者必须为“未运行”，不能由预置 SQL 代替。

### AC-22: CI 稳定门禁 [MUST]

Given 任意提交进入 CI
When 后端与前端流水线运行
Then lint、单元测试、确定性工作流测试、SQL 安全回归、离线检索评测契约和前端构建任一失败都会阻止通过，且 CI 不调用真实 LLM。

### AC-23: 可复现数据规模与负载报告 [SHOULD]

Given 固定随机种子生成的 10 万和 100 万行合成事实数据
When 在记录 CPU、内存、数据库版本、索引、并发和预热方式的环境中运行负载场景
Then 报告成功率、吞吐量、p50/p95/p99、超时率与慢查询；报告不得外推到未测试规模。

### AC-24: 资源清理 [MUST]

Given 查询成功、抛错、超时或客户端取消流
When 请求结束
Then 请求级数据库会话被释放，追踪进入一个终态，且下一次请求可以正常复用共享客户端。

### AC-25: 现有入口保持可用 [UNCHANGED] [MUST]

Given 客户端发送合法的 `{"query":"..."}` 请求
When 调用 `POST /api/query`
Then 仍获得 `text/event-stream` 响应；`GET /health` 仍返回服务健康信息。

### AC-C1: 工作流检查点续跑 [COULD]

Given 查询在可恢复节点后被进程中断
When 使用同一线程标识恢复
Then 已完成且有外部副作用的节点不重复执行，工作流从最近安全检查点继续。

### AC-C2: 追踪保留清理 [COULD]

Given 追踪已超过配置的保留期
When 清理任务运行
Then 过期追踪与事件被删除，未过期记录仍可回放。

### AC-W1: 公网多租户鉴权 [WONT]

本轮不实现账号、角色、租户隔离和计费；部署到公网前必须另立规格。

### AC-W2: 自动 Agentic RAG 升级 [WONT]

本轮不让模型自行选择任意工具或执行开放式研究；先把固定链路的安全、检索证据和评测补齐。

### AC-W3: 千万级能力声明 [WONT]

本轮不声明支持千万级数据；只有在目标硬件和真实索引上完成对应压测后才能新增该结论。

## Out of Scope

- 新增公网身份系统、租户与权限管理后台。
- 修改业务事实表和指标业务定义。
- 让自然语言请求执行写 SQL、管理 SQL 或任意用户 SQL。
- 用真实 LLM 作为 CI 硬依赖。
- 以单次本机实验给出生产容量承诺。

## Resolved Questions

- 安全策略错误立即终止；解析、白名单和数据库预检错误可以进入最多两次纠错，但每次都重新校验。
- SSE 保持 payload `type` 向后兼容，同时新增请求标识和唯一终态。
- 排名融合只在字段内部或指标内部进行，不跨字段、指标、业务值三类实体。
- 本轮必须完成审计回放；中断续跑作为 `[COULD]`，不能影响安全与评测主线。
- CI 使用确定性替身；真实模型、真实容器和规模压测分别报告，不互相冒充。

## Non-Functional Requirements

- 安全：遵守项目宪章中的只读、白名单、最小权限、超时、结果上限和秘密管理约束。
- 确定性：除显式真实模型评测外，相同输入和固定依赖必须产生相同测试结果。
- 可维护性：新增公共行为必须有稳定错误码、类型定义和测试；配置边界不能散落在节点中。
- 性能：安全校验 1,000 次本地基准的 p95 小于 10ms；确定性替身下 20 并发工作流全部在 5 秒内结束且无资源泄漏。
- 兼容性：现有 `/api/query` 请求格式、SSE payload `type` 与 `/health` 保持可用。
