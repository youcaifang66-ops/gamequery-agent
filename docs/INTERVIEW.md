# 面试深挖

## 为什么需要三路召回

字段语义、指标概念和字段真实取值属于不同类型的信息。把它们混在一个向量集合里会让相似度不可比较。字段与指标进入独立 Qdrant collection，枚举取值进入 Elasticsearch，随后通过 RRF 合并候选证据。

## 为什么 AST 检查不能被 EXPLAIN 替代

`EXPLAIN` 主要回答数据库能否解析和规划 SQL，不负责业务权限。AST 层先拒绝写操作、多语句、未知表和未知字段，并补充 LIMIT；数据库层再验证真实 MySQL 方言，两层解决的问题不同。

## 纠错如何避免死循环

修正节点完成后必须重新回到验证节点，状态中记录 `correction_attempts`。最多修正两次，超过上限直接终止并保留错误轨迹。测试覆盖一次修复成功和持续失败两条路径。

## 评测数字如何解释

20 条离线集合用于组件回归：12 条正确 SQL、4 条明确植入表名或字段名错误的 SQL、4 条攻击或越权 SQL。首次通过率 75% 是测试集构成导致的基线；修正后与执行结果均为 100%。它不能被表述为真实 LLM 的 Text-to-SQL 准确率。

## 下一步扩展

线上版本应按时间窗口积累真实问题，对 LLM 端到端统计执行准确率、结果集合一致性、首次成功率、平均修正次数、P95 延迟与 Token 成本，并将失败按召回、口径、Join、时间理解和 SQL 语法分类。
